**예측 갱신이 거래를 보장하지 않습니다.** 비용·현금·수량·정규장·주문 이후 완결 1분봉 조건을 충족해야 모의체결합니다. 하루 최초 배분 신호는 유지하며 같은 날짜 신호를 유리한 후속 전망으로 덮어쓰지 않습니다. 무료 일봉·1분봉은 초 단위 실시간 시세가 아닙니다.

## 디자인 7차를 운용 6차에 통합

**현재 기준:** 실험·운용 프로젝트는 6차입니다. 디자인 7차의 최신 Astryx 화면을 6차/web에 실제 교체했으며 기본 주소는 http://127.0.0.1:8879/ 입니다. 7차 화면 서버는 이전 디자인 검토 이력이며 기본 실행 경로가 아닙니다.

| 구분 | 통합 후 동작 |
| --- | --- |
| 실행 | 최종/대시보드 실행.cmd → 6차/server.py → 8879 |
| 화면 | 6차/web의 Astryx CSS·Rust 생성 테마·44px 조작부·라이트/다크 |
| 상태·작업 요청 | 같은 6차 서버의 기존 API로 직접 연결, 7차 프록시 의존 없음 |
| 데이터·모델 | 기존 1차 실행 환경·비공개 계좌·체크포인트 유지 |
| 실행 중인 작업 | 화면 교체를 위해 서버·학습을 중단하거나 재시작하지 않음 |
| 검사 | 동일 화면의 기존 독립 검사 재사용, 6차 제공 파일·실행 연결만 추가 확인 |

구 화면은 활성 화면에서 교체했으며 비공개 변경 이력으로만 보존했습니다. 이전 실험·원문 비교·검사 이력은 유지합니다. 화면 통합은 예측 성능·수익 개선을 입증하지 않습니다.

## 테마 재생성과 보존 범위

테마생성.py·테마설정.json·공식 MIT/OFL·자체 Rust 원문을 6차에 함께 넣었습니다. 화면 실행은 포함된 CSS만 읽어 7차 폴더나 Rust 재빌드를 필요로 하지 않습니다. 재생성은 기존 E:/2026/Astryx 공통 디자인/1차의 Rust 실행 파일과 공식 npm @astryxdesign/theme-neutral 0.7.17을 사용합니다. `cargo build --release --manifest-path "의존성/Rust 테마 엔진/Cargo.toml"`은 보존 원문 빌드 방법입니다. 기존 두 모드 실제 호출·CSS 일치 근거를 재사용했으며 이번 통합에서 재빌드하지 않았습니다.

저장 체크포인트가 있으면 기존 엔진이 가중치를 재사용합니다. 옵티마이저 상태까지 완전히 이어지는 재개로 표현하지 않습니다. 연속 운용은 새 데이터가 있을 때 추가 학습하며 기다리는 상태에서는 학습 횟수가 늘지 않을 수 있습니다. 학습·모의거래는 서로 다른 조건으로 실행됩니다.
